# QA Checklist（小星手绘版）

## 必过项

- 是 16:9 横版。
- 背景是干净白底（无米色、纸纹、渐变、阴影、噪点）。
- 黑色手绘线稿：细线、轻微抖动；不是 3D、不是写实、不是精致渲染。
- 小星在场，小小的一只：全身占画面高度 ≤1/3（目标 ~1/4），远景全身；且是核心动作的执行者，不只是装饰。
- 形象锁定项可辨认：短碎发＋蓝灰挑染、星星发夹、星星耳坠、条纹衬衫＋绿领巾、阔腿牛仔裤。
- 脸没走样：对照 `references/character/face-closeup.jpg` 验脸；生成 / 改图不许换脸。
- 一张图只讲一个核心结构；主体（含小星与物件）占 40%-60%，留白 ≥35%。
- 中文标注 ≤8 处、短、可读。
- 橙色只用于主路径或箭头；红色只用于重点、问题、提醒或结果；蓝色只用于补充说明、反馈或系统状态。
- 淡绿只出现在绿领巾，淡蓝灰只出现在挑染；不超标。
- 没有复刻旧案例构图，而是为当前文章生成了新隐喻。
- 无左上角类型标题。

## 失败信号

出现以下情况，重生成或局部编辑：

- 小星被画成 3D 人偶、写实人物或精致插画。
- 脸部走样 / 换脸（对照脸部特写锚点）。
- 小星太大（全身超过画面 1/3 高）或近景大头贴 → 直接判废重画，不做局部修改。
- 左上角有"常见坑 / Workflow / 系统架构图 / 路线图"等标题。
- 画面像 PPT、课程课件、正式流程图。
- 元素太多、箭头太多、节点太多。
- 文字变成大段解释。
- 背景有纸纹、阴影、渐变、米色、噪点。
- 真实 UI 截图或科技感界面。
- 中文错字严重或标注不可读。
- 画面太死板，没有荒诞隐喻。
- 和 `assets/examples/` 里的旧案例构图过于相似。

## 迭代方法

- 走样：用"修正形象走样"编辑提示局部修；修不好就重生成并附基准图（注明仅取设计元素）。
- 被画成 3D / 写实：重生成，强调 hand-drawn line art、NOT 3D、NOT photorealistic。
- 太大：强调 tiny figure（≤1/3 画面高度）、wide shot。
- 太普通：放大"小小的人 vs 巨型物件"的体型反差，让小星亲手推动结构运转。
- 人物太大：判废重画，不要修修补补；重画时先铺大场景，再把小小的小星放进去。
- 太复杂：删节点，只保留一个动作和 3-5 个短标注。
- 太 PPT：去掉标题、边框、整齐网格和过多箭头，换成小星在场景里亲手做事。
- 太像旧案例：保留核心意思，换掉主物件和小星动作。
- 文字错：优先局部编辑；错得多就重生成并减少标注数量。

## 交付判断

高质量图应该让读者先觉得"有点怪"，然后 1 秒内看懂结构。

如果第一眼像教程页，而不是白纸上的手绘草图，就不合格。
